# AiR Source Repository Audit

## Product foundation

The selected `borngifted/air` repository establishes **AIR — AI Readiness** as a free, action-led learning experience sponsored by Digi2U.org. Its strongest strategic idea is that learners should begin with a human outcome rather than an AI tool, then direct, inspect, revise, and release useful work. The recurring language—**Clear the air**, **Human before tool**, **Challenge the result**, and **Put it in the world**—will anchor the expanded platform.

| Source strength | Reuse decision |
|---|---|
| Distinctive forward-leaning AiR mark | Preserve as the central brand asset and motion motif |
| Deep green, ivory, bright green, and lime palette | Preserve, refine into a complete accessible token system |
| Explore / Create / Build entry modes | Preserve as flexible practice modes inside each learning path |
| Eight-step learner journey | Expand into four structured learning paths with connected lessons and visible progress |
| Reflection widgets and practice exercises | Rebuild as authenticated, database-backed lesson interactions |
| Human-before-tool teaching philosophy | Make it the primary curriculum and messaging principle |
| Static browser-local progress | Replace with persistent member progress and resumable profiles |
| Static facilitator entry | Replace with a distinct admin/trainer knowledge base |
| AIR Radio / podcast block | Exclude completely from routes, copy, components, and navigation |

## Experience principles

AiR should not look or feel like a conventional learning-management system. It will use strong editorial pacing, oversized athletic typography, compressed labels, forward-slanted geometry, and action verbs. Progress will remain visible, but will be framed primarily as **moves completed**, **work made**, and **ideas shared**, not as grades, certificates, or status theater.

The public platform will use a top navigation and high-impact landing experience. Authenticated learning and community pages will retain the same brand shell rather than switching to a generic enterprise dashboard. The separate trainer knowledge base will use a denser documentation layout appropriate for facilitation, preparation, and source review.

## Curriculum direction

The source materials support a practical curriculum organized around a repeatable operating system:

| Stage | Learner action | Evidence of learning |
|---|---|---|
| Clear | Remove hype and name one human outcome | A mission statement |
| Direct | Turn intent into a useful brief | A structured direction prompt |
| Make | Generate options and shape a real artifact | A draft or prototype |
| Judge | Verify facts, fit, bias, accessibility, and risk | A documented review |
| Build | Convert the useful pattern into a repeatable workflow | A reusable process |
| Release | Put the work in front of a real person | A published artifact and reflection |

These stages will become connected learning paths for **Mindset**, **Making**, **Judgment**, and **Momentum**, with video-led lessons, reflection checkpoints, practical exercises, completion records, and discussion prompts.

## Community direction

The existing repository has no persistent community. The rebuild will add authenticated profiles, onboarding, course progress, posts, comments, and lesson-linked discussions. Community participation will be oriented around practice: members share what they tried, what changed, what failed, and what they will do next.

## Trainer knowledge base direction

The trainer knowledge base will generalize the source facilitator guide into a repeatable delivery system. Each trainer resource will include purpose, learner promise, preparation, timing, facilitation script, differentiated Explore/Create/Build activities, reflection prompts, common failure modes, accessibility guidance, delivery variations, and source references. Trainer resources will be kept in their own persistent content model and separate route family.

## Media decision

The source repository contains reusable logo, poster, atmospheric video, and course-scene assets. The rebuilt site may reuse visual media through managed storage, but it will not include any audio podcast or player. Video lessons will support text transcripts, in-lesson prompts, reflection checkpoints, exercises, and clear actions into the community.
